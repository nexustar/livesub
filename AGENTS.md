# livesub — notes for developers and agents

Real-time bilingual captions: a Node/TypeScript server and a static browser
frontend. User-facing docs are in `README.md`; this file holds only what you
need to change the code safely.

## Layout

- `src/server.ts` — HTTP routes (`/api/backends`, `/api/models/*`, `/api/hints`, static files), the `/ws` endpoint, startup.
- `src/pipeline.ts` — the per-session `Pipeline`: audio in, the ASR workers (qwen, voxtral, openai-realtime, dashscope, gemini), sentence segmentation, translation, events out to the client.
- `src/config.ts` — env, translate-backend registry, Qwen model registry, data dir, where the qwen binary comes from (`QWEN_ASR_BIN`, then the `quickasr` npm package or the older `qwen-asr`, then `quickasr` on `PATH`), and the devices it can run on (`quickasr --list-devices json`).
- `src/models.ts` — model downloads behind `/api/models` (Qwen and the local translation models).
- `src/mt.ts` — local translation: language names to model codes, routes (pivot through English), the worker pool; `src/mt-worker.ts` runs the engine; `src/mt-models.ts` is generated by `scripts/gen-mt-models.mjs`.
- `vendor/bergamot/` — Firefox's translation engine (WASM + JS glue, MPL-2.0), refreshed by `scripts/vendor-bergamot.mjs`.
- `src/prompts.ts` — translation prompts and `PairedStreamParser`; `src/hints.ts` — `/api/hints`; `src/util.ts` — queue, logger, helpers.
- `static/` — the frontend: vanilla JS/HTML/CSS, no build step, one file per role; `i18n.js` holds the UI translations.
- `bin/livesub.mjs` — the CLI; `scripts/` — manual check scripts (not shipped, no test runner).

## Run, verify, release

- `npm install`, then `npm start` (http://127.0.0.1:8000; `LIVESUB_HOST` / `LIVESUB_PORT`, or `--host` / `--port` on the CLI). `.env` / `livesub.toml` are read from the working directory.
- After editing `src/`: `npm run typecheck`. There are no frontend tests: check UI changes in a browser.
- UI text: wrap it in `t()` (or `data-i18n` in the markup) with the English as the key, add the zh entry to `static/i18n.js`, then `node scripts/check-i18n.mjs`. `README.md` and `README.zh-CN.md` change together.
- The qwen binary comes from the optional dependency `quickasr` (prebuilt, built from github.com/nexustar/quickasr; `qwen-asr` before the rename); a `QWEN_ASR_BIN` in `.env` overrides it. Each Qwen model row in Settings has a device picker next to the chunk slider (cpu by default, never chosen automatically); the pipeline passes it as `--device`, and a GPU failure quickasr reports on stderr becomes a UI error.
- Before changing a default model: `npx tsx scripts/bench-models.ts translate [sdk:model ...]` (or `hints`), N>=12 rounds; small samples swing by 2x.
- Release: push a `v*` tag; `.github/workflows/release.yml` tests the packed package and publishes it (prereleases on the `next` tag). The tag sets the version.

## Tuned behaviour — don't change without understanding why

Each has a comment at the site.

- `pipeline.ts`: the leading-space lstrip in `onTranscriptChunk` and `cut <= 0` (not `< 0`) in the length fallback — both prevent stalls; the `<=256`-char slicing in `onTranscriptText` — piped subprocess output arrives in bursts that would otherwise become huge segments.
- qwen-asr flags: keep `--skip-silence` and `--past-text yes`, don't add `--repeat-penalty`, and don't pass a `--prompt` (the model copies term lists into the transcript; the glossary goes to the translator).
- Pre-buffer replay on silence→speech, or word onsets get clipped.
- Gemini ASR (`gemini-3.5-transcribe-live`): automatic VAD stays disabled with one manual `activityStart` per session (its VAD misses speech in noisy audio), no `systemInstruction` (bias via `customVocabulary`). Interims are a growing full-replace hypothesis, consumed with a tail hold-back (`GEMINI_INTERIM_HOLDBACK_CHARS`). A final arrives after about 220 s of audio and the session goes quiet after it: flush and reopen.
- `PairedStreamParser` holds back any partial `</curr>` so a closing tag never streams into the caption.
- `safeSendJson` awaits the ws flush (client backpressure, send errors).
- Client: a failed revision (`translation_done` with `ok: false`) keeps the previous translation; `stop()` clears `ws.onclose` so only closes we didn't ask for reach it. Those reconnect on the same audio capture with backoff (close code 1003 = config refused, final; sessions that open and fail repeatedly give up), replaying up to 15 s of audio captured meanwhile; each new session restarts sids at 0, so on-screen sentences are retired to history first.
- Thinking-off is per model on the Anthropic SDK path (`anthropicThinkingOff`): `claude-sonnet-5-5` needs `{type: "between_tools"}`, others `disabled`; probe a new Claude model before adding it. Gemini translate uses `thinkingLevel: MINIMAL` (`thinkingBudget: 0` 400s on 3.5); default stays `gemini-3.1-flash-lite` (3.5 measured slower; re-bench before 3.1's 2027-05-07 shutdown).
- Hints: keep `web_search_20250305` (newer versions slower and costlier), `max_tokens: 4096` (thinking counts against it), the effort levels (Claude `medium`, DeepSeek `low`) and the prompt's "search even when you feel confident" rule (without it, lower effort answers from stale training data). Gemini hints stays `gemini-2.5-flash` (no free-tier Search grounding on 3.x). DeepSeek hints use the same tool through its Anthropic-compatible endpoint; it ignores `max_uses` and drops closing tags, which the parser tolerates. The search engine is the UI's pick (`/api/backends` → `hints`); `HINTS_BACKEND` is only the default.
- Request guards (`server.ts`): an Origin must match the server and, on loopback, so must the Host. WebSockets bypass CORS, and DNS rebinding makes any page same-origin; don't drop either check.
- Model downloads: files land as `.part` and are renamed only after the size and sha256 check; the HF revision, sizes and hashes in `QWEN_MODELS` change together. Model POSTs require a JSON content type so other sites can't trigger multi-GB downloads.
- Frontend: polled UI (model rows, the welcome card) is updated in place, not rebuilt, so a click isn't lost mid-poll; `#settings-panel [hidden] { display: none }` must stay, as row/button display rules otherwise beat the `hidden` attribute.
- Pop out moves the `#caption-stack` node itself into the Document PiP window, so caption code must keep using the element references taken at load, not `document.getElementById` at render time; body classes the caption CSS needs are mirrored (`PIP_BODY_CLASSES`).
- i18n: text that code rewrites (status line, Start/Stop) must not carry `data-i18n`, or a language switch resets it; `setStatus` takes the English key so the status can be re-rendered.
- Local translation (`mt.ts`, `mt-worker.ts`): the WASM and JS glue are the pair one Firefox release ships; bump both together. It runs in a worker thread because the engine is synchronous (20-170 ms a sentence). Decoder options are Firefox's. `TranslationModel` needs real language codes (the WASM splits sentences with `Intl.Segmenter`). Node has no `mozIntGemm`, so the WASM's fallback gemm runs (about 1.5x native). Models come from Remote Settings, not Mozilla's model bucket, whose runs don't always hold the shortlist Firefox ships; their zstd needs Node 22.15+.
- Model IDs were last re-evaluated 2026-10 with measurements; confirm before bumping.

## Conventions

- Comment density high; match the existing style. No emojis in code.
- One module per role; no premature abstractions.
- Log with `log.*`, not `console.log`; keep `log.info` under ~100 per session.
- Use the vendor's JS SDK rather than hand-rolled HTTP.
- Commits: short imperative subject (`Area: what changed`), a few lines on why; author `nexustar <inexustar@gmail.com>`.
